# ARANDU - Agent Instructions & Full-Stack Architecture Context

## 1. Project Overview
**Arandu** is a modern, premium digital newspaper and classifieds catalog platform designed for the Spanish-speaking community in Geneva, Switzerland. The platform connects local cultural journalism with neighborhood service directories. It is divided into a public website (`frontend-public`) and a protected administration console (`frontend-admin`).

## 2. Tech Stack
* **Frontend:** Angular 18 (Standalone Components ONLY).
* **Styling:** TailwindCSS.
* **Maps:** Leaflet.js.
* **Backend:** NestJS with Drizzle ORM.
* **Database & Auth:** Supabase (PostgreSQL).
* **AI Engine:** Groq API (Strictly for fast cloud inference and JSON structuring).
* **Infrastructure:** OVHcloud VPS managed via Coolify.

## 3. Core Frontend Constraints (Strict Rules)
All frontend code generated by the agent MUST adhere to these OpenSpec constraints:
1. **Framework:** Use Angular 18 strictly with Standalone Components. `NgModules` are strictly FORBIDDEN.
2. **State Management:** Use Angular Signals (`signal`, `computed`, `effect`) exclusively for component state.
3. **Strict UI DOM:** The DOM structure of the public view MUST mathematically match the Builder preview canvas (WYSIWYG).
4. **Scroll Discipline:** Nested scrolling is forbidden. The main view must use `overflow-x-hidden`. Never inject `overflow-auto` into child text containers.
5. **TailwindCSS Only:** Styling must be handled exclusively through Tailwind utility classes. Do NOT create custom CSS stylesheets.
6. **Floating Toolbars:** Do not build global design/configuration buttons. Layout formatting must be done in-place via floating context menus positioned absolutely (`z-index: 50`) above active elements.

## 4. Backend & AI Workflow (The RSS Pipeline)
* **RSS Ingestion:** The NestJS backend uses Cron Jobs to autonomously read local Geneva RSS feeds. Web scraping is NOT used for news.
* **Groq Processing:** NestJS sends raw XML/HTML to the Groq API. Groq filters noise, extracts key entities (neighborhoods, politicians), and translates the content to Spanish.
* **OKF Standard:** The agent MUST use Groq's Structured Outputs to return a strict JSON following the Open Knowledge Format (OKF). The JSON must contain: `type`, `contenido`, `procedencia` (original URL), `metadatos`, and `entidades`.
* **Multimedia:** Images found in RSS feeds must be downloaded, converted to WebP via Sharp in NestJS, and uploaded to Supabase Storage to prevent hotlinking.

## 5. Zero-Trust Security & Moderation
The public frontend allows anonymous users to leave 1-to-5 star ratings, "likes", and comments. Before inserting any interaction into Supabase, the backend MUST implement a triple security barrier:
1. **Rate Limiting:** Implement `@nestjs/throttler` to limit interactions (e.g., max 5 comments/stars per IP per hour).
2. **Human Validation:** Ensure Turnstile or reCAPTCHA is integrated into the Angular frontend to block bots.
3. **Toxicity Guardian:** NestJS must send the comment text to the Groq API with a strict JSON format prompt. If Groq returns `{"toxic": true}`, the interaction is rejected instantly.

## 6. Agent Operational Directives & Anti-Hallucination
* **No Hallucinations:** Do not add external dependencies (like random Node.js servers, external libraries, or Python scripts) unless explicitly requested. Use vanilla TS/JS within the Angular/NestJS ecosystem.
* **Clarification Phase:** Before writing complex full-stack features, prompt the user with questions to clarify requirements (simulate the `/grillme` behavior).
* **Autonomous Execution:** When creating parallel subagents for tasks (e.g., Frontend and QA), execute autonomously without asking for manual confirmation loops on terminal commands.
* **Admin Boundaries:** Always keep the distinction between `frontend-public` and `frontend-admin`. Non-admins attempting to access the admin console must be intercepted, signed out from Supabase, and shown an "Access denied" error.
